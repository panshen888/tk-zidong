# TikTok AI Flow 持久任务计划

## 目标

当前项目目标已从早期 Excel MVP 升级为完整的 TikTok 跨境选品上架自动化工具：

`表一输入 -> AI比价 -> 表二候选 -> 表三待人工核实上架 -> AI上架编辑表 -> 妙手采集/认领/保存草稿/确认发布`

采购模块暂不在本阶段内，后续单独开 AI采购 卡片。

## 当前优先事项

0. 2026-06-17 软件复测结论：当前源码构建可跑通 AI比价和表三生成；安装版需要重新覆盖打包，否则 preload 可能缺少最新 DOM 发布接口。表三生成后仍为 `待核实`，AI上架只读 `已审核`，因此需要用户人工审核或新增明确的“确认当前表三并进入上架”按钮。
1. 保持当前 4 表架构稳定，不再恢复旧的待上架商品表、刊登任务表、AI上架审核表、采购任务表。
2. AI比价继续以表三为上架衔接点：表二多候选、表三唯一推荐，表三 `已审核` 才进入 AI上架。
3. AI上架当前分两层：AI上架编辑表承接采集、认领、店铺绑定和待执行数据；浏览器模拟保存并发布的执行结果写入 AI上架结果表。
4. 发布结果复核已接入 AI上架编辑表：查询妙手采集箱 `published / timingPublish / notPublished` 状态，写回复核状态、妙手状态、TikTok 商品 ID/链接（如果接口返回）。
5. 多国家/多店铺映射已接入上架配置：生成 AI上架编辑表时按表三站点选择目标店铺，MY/SG/PH/VN/TH 可各自映射。
6. 已发布商品维护入口已建立：当前只准备维护状态，后续二次改价、改重量、改尺寸单独实现，不混进首次上架流程。
7. 旧上架/采购四表链路保留为停用代码路径，默认调用会直接报错，不再创建 `待上架商品表`、`刊登任务表`、`AI上架审核表`、`采购任务表`。
8. 采购模块继续独立，不在当前 AI上架阶段内实现。
9. 表三物流字段边界：只保留并写入 `跨境物流成本（当地货币）`；`跨境物流成本(CNY)` 已剔除。其它 CNY 成本字段如 `采购总成本（CNY）`、`平台处理费/CNY`、`货代费用(CNY)`、`其他费用(CNY)` 保持不变，供利润公式使用。
10. 新电脑/无妙手接口权限边界：AI比价和表三人工核实可继续使用；AI上架必须开启 `启用妙手接口上架` 并配置妙手开放平台，否则软件和主进程都会拦截妙手相关动作。
11. 浏览器模拟发布入口需要增加执行范围保护：优先只处理本次生成的 AI上架编辑记录，或按 `表三记录ID / 商品ID + 国家/站点 + 目标店铺ID` 限定，避免全表扫描误发布历史记录。
12. 多站点展示价字段需要继续收口：VN/TH/PH/SG/MY 不应固定读取 `本地展示价(折后)(MYR)`；上架前应按站点读取对应币种字段或通用 `本地展示价` 字段。
13. 2026-06-17 最新定价边界：当前上架链路优先使用“妙手定价模板引用”生成本地展示价。表三 `本地展示价(折后)(MYR)` 及其它站点展示价字段不再作为必填；如果目标站点已配置妙手定价模板，浏览器模拟发布允许展示价为空，执行器在妙手页面批量改货源价和克重后引用模板生成展示价。只有目标站点未配置妙手定价模板时，才要求表三或 AI上架编辑表存在大于 0 的本地展示价。

## 验收标准

- `npm run lint` 通过。
- `npm run typecheck` 通过。
- `npm run build:app` 通过。
- `npm run mock:excel` 可生成测试 Excel。
- `npm run verify:excel` 可完成 Excel 读取、图片缓存与输出表生成。
- `npm run inspect:excel` 可确认输出 Excel 已回填候选链接与候选 Sheet。
- 真实 1688 任务使用应用独立 Chrome；用户可先点击“打开登录浏览器”完成 1688 登录。
- `SKU匹配结果` Sheet 可确认详情页 SKU 匹配、采购成本价、运费、尺寸、克重已落盘。
- 全局配置可保存 AI 中转站 Base URL、API Key、模型名、同款阈值。
- AI智能比价页以表格展示任务列表，创建任务通过弹窗录入 Excel、候选数、相似度达标采纳条数与详情页解析开关，点击执行后生成一条独立执行日志。
- Excel 从第 2 行开始读取真实数据；遇到首个完全空行即停止，不继续读取后续行。
- `原商品主图URL` 列既支持图片对象/内嵌图片，也支持 URL/超链接对象，不应再出现 `[object Object]` URL 解析错误；结果 Excel 中该列需保持与原 Excel 一致，本地缓存路径写入 `原商品主图本地路径`。
- 默认候选链接数为 50。
- 默认并发配置：任务级 1、Excel 行 3、详情页 3、AI 请求 8。
- 单任务内 Excel 行与详情页下钻支持并发处理，并对 1688 页面访问做轻微随机错峰；AI 相似度请求共享全局并发限制。
- 默认 AI 模型为 `gpt-5.5`。
- 相似度达标采纳条数默认 10；只对达标候选按相似度倒序采纳前 N 条进入详情页。
- 任务与执行日志为一对多关系；日志列表按时间倒序，任务删除会删除所有相关日志资产，单条日志删除只删除该 run 的输入、输出、日志和资产。
- 每条 Excel 数据先对列表页候选封面做相似度筛选，只有相似度达标候选才进入详情页。
- `1688候选供应商` Sheet 复用为价格最低 Top3 结果；`SKU匹配结果` Sheet 复用为每个原商品最优 1 条结果，不新增更多结果 Sheet。
- Chrome 调试地址、Chrome 用户数据目录、Chrome 调用方式不暴露给用户；只保留 Chrome 可执行程序选择与登录浏览器按钮。
- 真实 1688 搜图会先写入 `input.image-file-reader-wrapper`，再等待上传预览弹窗并点击“搜索图片”，然后在新打开结果页继续解析。
- 结果页从 `#offer-list-content [data-tracker="offer"][data-index]` 等卡片中解析前 50 个候选封面 URL，并优先一次调用 AI 返回 50 个顺序相似度分数。
- 详情页对达标候选打开详情页，优先读取 SKU 列表中的商品图片，一次调用 AI 批量比较，选中最高相似 SKU；如果 SKU 列表无商品图片，则该候选详情验证失败并记录原因。
- 详情页必须先确认价格阶梯存在 `1个起批` / `1件起批` 等“数量 1 + 单位 + 起批”字样；未确认或不是 1 个/件起批时，该候选详情验证失败并记录原因。
- 选中匹配 SKU 时必须触发 click，再将对应数量输入框设置为 1 或点击加号设为 1，等待 `.order-select-models` 显示已选 1 个后读取商品金额与预估运费；不再依赖加购弹窗计价，也不扣减新客/首单优惠。
- 尺寸与克重优先从“商品件重尺”表按 SKU 名称匹配；不足时再从页面文本正则和 AI 文本抽取兜底。
- 运行中的任务可点击“中断”；任务使用协作式取消，会在当前关键异步步骤完成/抛错后尽快停止，并将当前执行日志标记为 `cancelled`。
- 登录浏览器固定可见，仅用于人工登录/验证码/风控；任务执行可配置为无头后台或有头低打扰模式。
- 无头后台模式执行前会关闭应用独立可见 Chrome，并复用同一独立用户目录登录态；不会关闭用户日常 Chrome。
- 有头低打扰模式不调用 `bringToFront()`，并通过 `--start-minimized`、屏幕外窗口位置等参数尽量降低打扰；非 headless 模式不能保证所有系统完全不弹前台。
- AI上架真实闭环不自动发布；妙手返回的主图、详情、SKU 图、完整 SKU Map 和 ossMd5 不写入飞书表；保存草稿前重新读取最新详情，只统一写 `originPrice`、`priceIncludeVat`、重量和尺寸。
- AI上架编辑表中的尺寸缺失默认写 `10*10*10cm` 对应长宽高；克重缺失进入需人工处理，不保存草稿。

## 2026-06-24 清晰补充：v0.1.4 类目匹配、尺码表与必填属性边界

- 当前主链路仍保持 5 张飞书表：`输入表`、`输出货源表`、`待人工核实上架表`、`AI上架编辑表`、`AI上架结果表`。
- `目标站点类目` 已从输入表流转到表二、表三和 `AI上架编辑表`，用于匹配妙手 TikTok 类目树。
- 妙手类目树按目标站点刷新和缓存，类目匹配优先使用 `pathChinese/nameChinese`，再兜底 `path/name`；命中后必须是末级类目且未禁用。
- 当前实测 VN 类目树返回 2596 个节点，其中可用末级类目 667 个；`女装与女士内衣 > 女士睡衣和家居服 > 女士睡裙` 可唯一命中 `cid=846088`。
- 尺码表不写死，使用 AI上架配置里的 `尺码表网络图片URL`；保存前根据 `get_category_metadata` 判断是否必填，必填时写入 `sizeChartType=image` 和配置 URL。
- 妙手保存 payload 已做保护：图片列表最多 15 张，缺少 `deliveryOptionSetType` 时补 `default`，商品重量必填，包裹尺寸缺失或过小时按至少 `1cm` 写入。
- 发布前不再用表三源站点拦截目标店铺，目标站点和目标店铺以 AI上架配置为准，例如 MY 来源允许上架到 VN 目标店铺。
- `get_category_metadata` 现在会预检查必填商品属性；如果妙手详情里缺少必填属性，提前写入 `需人工处理`，不再等保存接口失败。
- 当前真实卡点：VN `cid=846088` 的元数据返回 `材质` 为必填属性。按当前安全边界，程序不自动乱填材质、品牌、认证、责任人等字段，先写明 `妙手类目必填属性缺失：材质，需人工在妙手补充后重试`。
- 下一步如需继续自动化，应单独设计“按站点/类目配置必填属性默认值”的配置，例如 `VN|846088|材质=涤纶（聚酯纤维）`，再映射妙手元数据里的属性 ID 和选项 ID 后写入。

## 2026-06-24 清晰补充：v0.1.5 必填属性材质下拉配置

- 用户确认：`材质` 默认值不做手输文本，直接做成可下拉配置。
- 下拉来源：按当前 `目标站点 + 目标类目ID + 目标店铺ID` 调用妙手 `get_category_metadata`，读取该类目必填属性里的 `材质` 可选项。
- 配置保存：按 `站点|类目ID|属性名=选项名` 存储，例如 `VN|846088|材质=涤纶（聚酯纤维）`。
- 上架执行：程序拿到实际匹配类目 `cid` 后，如果该类目元数据要求 `材质`，且妙手详情里没有该属性值，就按配置匹配元数据选项并写入 `productAttributes`。
- 安全边界：只有元数据里能匹配到该选项时才写入；匹配不到则失败并写 `材质默认值未命中妙手选项`。其它必填属性暂不自动填写。
