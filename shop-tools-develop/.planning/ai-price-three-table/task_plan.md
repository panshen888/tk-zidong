# AI比价三表流程项目计划

创建时间：2026-06-12

## 目标

把现有 AI比价模块整理成稳定的三表闭环，并为后续 AI上架/妙手采集提供唯一、可审核的数据入口。

核心链路：

`输入表 -> 输出货源表 -> 待人工核实上架表 -> AI上架/妙手采集`

当前计划只覆盖 AI比价三表和模板能力，不实现妙手采集、利润筛选、采购流程。

## 当前结论

状态：AI比价三表闭环已跑通。

已完成真实链路验证：

- 表一可从郑和数据链接补齐 `商品ID`、`国家/站点`、`原商品链接`、`原商品主图URL`。
- 真实 1688 搜图、AI列表相似度、详情页 SKU/价格/运费/克重/尺寸解析可写入表二。
- 表二默认进入 `商品组状态 = 待核实`，不自动生成表三。
- 人工将表二商品组状态改为 `已核实` 或 `待更新表三` 后，再生成表三。
- 自动生成表三已限定为当前 `比价批次号`，避免新任务扫描旧已核实商品组。
- `起批量` 只作为参考/风险值记录，不再作为表三硬性失败条件。

## 范围

包含：

- 飞书三表字段模板创建。
- 本地三表 Excel 模板导出。
- 表一输入解析、去重、批次号生成。
- 表二候选货源输出、商品组状态和候选状态管理。
- 表三唯一推荐货源生成、人工指定优先、克重多数决策。
- 配置页增加三表 tableId/viewId、克重容差、自动生成开关、模板按钮。
- 表二状态扫描时，同组 `商品组状态` 自动同步。

不包含：

- 表三利润字段。
- AI上架利润审核。
- 妙手采集执行。
- 妙手自动发布。
- 采购下单流程。

## 已锁定规则

- 业务唯一键：`商品ID + 国家/站点`。
- 每次手动重跑生成新 `比价批次号`，格式：`cmp_yyyyMMdd_HHmmss_随机4位`。
- 表二旧候选不删除，表三只使用同商品同站点的最新批次。
- 重复检测覆盖表一、表二、表三，失败记录也参与拦截。
- 候选数量读取配置 `候选生成数量`，不固定 Top3。
- 找到 0 条候选时，表二仍创建一条失败占位记录，`候选序号 = 0`。
- 表三生成失败时，也要创建或更新失败记录，让人工能看到原因。
- 表二保留两个状态：`商品组状态` 和 `候选状态`。
- 手动修改一行表二 `商品组状态` 后，下一轮扫描同步同组所有行。
- 表三第一版不放利润字段，利润后续进入 AI上架或独立审核表。
- `起批量` 仅记录到表二/表三和风险备注，不拦截候选，也不作为表三失败归因。
- 自动任务写完表二后，如果开启自动生成表三，只扫描本次 `比价批次号` 对应商品组。

完整字段和状态枚举以 `docs/ai-price-three-table-workflow.md` 为准。

## 阶段计划

### 阶段 1：配置与类型设计

状态：complete

任务：

- 在共享类型中增加三表配置字段。
- 在默认配置中补齐默认值。
- 保留现有比价配置，不破坏已录入配置。
- 明确 AI比价配置和 AI上架配置边界。

验收：

- 配置可保存。
- 保存后立即生效，不需要重启。
- 旧配置缺字段时能自动补默认值。

### 阶段 2：飞书三表模板

状态：complete

任务：

- 增加 `创建飞书三表字段` 按钮。
- 若表不存在则创建表。
- 若表存在则补缺字段。
- 不删除字段，不修改已有字段类型。
- 字段类型冲突时停止并提示 `字段类型不匹配`。

验收：

- 能在同一个多维表内生成 `输入表`、`输出货源表`、`待人工核实上架表`。
- 所有锁定字段存在。
- 已有字段不被误改。

### 阶段 3：本地 Excel 三表模板

状态：complete

任务：

- 增加 `导出本地三表Excel模板` 按钮。
- 生成一个 `.xlsx` 文件。
- 包含三个 sheet：`输入表`、`输出货源表`、`待人工核实上架表`。
- 只生成表头，不写示例数据。

验收：

- Excel 能正常打开。
- 三个 sheet 字段顺序和锁定文档一致。

### 阶段 4：表一输入处理

状态：complete

任务：

- 从表一读取 `待处理` 记录。
- 优先解析郑和数据链接，补齐商品ID、国家/站点、原商品链接、原商品主图URL。
- 如果已录入主图 URL，则沿用原逻辑。
- 按 `商品ID + 国家/站点` 检查三表重复。
- 生成并写入当前比价批次号。
- 失败时写 `状态 = 失败` 和 `失败归因`。

验收：

- 可处理郑和链接入口。
- 可处理原主图 URL 入口。
- 重复记录被拦截并写明重复位置。

### 阶段 5：表二候选输出

状态：complete

任务：

- 将现有比价结果写入表二。
- 写入候选序号、采购价、运费、采购总成本、克重、尺寸、SKU、相似度、起批量等字段。
- 候选不足但大于 0 时写风险备注，不直接失败。
- 0 候选时创建失败占位行。
- 支持表二同组状态同步。

验收：

- 每个输入批次对应一组表二候选。
- 失败原因落到表二 `失败归因`。
- `商品组状态` 与 `候选状态` 含义不混淆。

### 阶段 6：表三推荐生成引擎

状态：complete

任务：

- 读取表二 `商品组状态 = 已核实 / 待更新表三` 的商品组。
- 按 `商品ID + 国家/站点` 新增或更新表三。
- 人工指定候选优先。
- 未指定时按克重容差分组，多数决策。
- 命中组内选择采购总成本最低候选。
- 对表三硬校验字段做失败映射。
- 已存在妙手字段时按锁定规则保留并追加风险备注。

验收：

- 成功时表三 `状态 = 待核实`。
- 失败时表三 `状态 = 失败` 并写 `失败归因`。
- 多选人工指定会失败为 `人工指定多条候选`。

### 阶段 7：配置页与执行入口

状态：complete

任务：

- 在 AI比价配置下增加三表配置和模板按钮。
- AI上架配置独立放在 AI上架模块下。
- 增加手动生成表三入口。
- 自动生成表三开关默认关闭。
- 展示固定规则说明，避免配置项过多导致误操作。

验收：

- 页面分区清楚：AI比价配置和 AI上架配置分开。
- 用户能手动创建模板、导出模板、生成表三。

### 阶段 8：验证与回归

状态：complete

任务：

- 用 1 条郑和链接跑通表一到表二。
- 人工将表二商品组状态改为已核实。
- 生成表三唯一推荐货源。
- 测试人工指定、候选不足、0 候选、缺克重、起批量不为 1、字段类型冲突。
- 跑类型检查、lint、构建。
- 用真实 AI 配置跑通郑和链接 -> 1688 -> 表二候选写入。
- 验证没有待处理记录时执行脚本会安全跳过。

验收：

- `npm.cmd run typecheck` 通过。
- `npm.cmd run verify:price-three-table` 通过。
- `npm.cmd run build:electron` 通过。
- 飞书和本地 Excel 两版模板均可用。
- 真实飞书表二候选写入成功，表三生成边界符合人工核实规则。

## 风险与约束

- 飞书字段类型一旦建错，不自动修改，避免破坏已有数据。
- 视图 viewId 只限制读取范围，写入和同组同步必须操作整张目标表。
- 郑和数据接口或页面结构变化会影响入口解析，需要把失败原因写清楚。
- 1688 登录、验证、反爬会影响候选获取，但不改变三表状态规则。
- 妙手采集属于 AI上架，不能混入本阶段比价执行。

## 下一步

AI比价阶段进入维护状态。

后续开发从 AI上架模块继续：

- AI上架只读取表三 `状态 = 已审核` 的记录。
- 先做妙手采集/编辑准备，不做自动发布。
- 利润筛选、前端售价、妙手定价模板放在 AI上架或独立利润审核表，不回塞到 AI比价表三。
