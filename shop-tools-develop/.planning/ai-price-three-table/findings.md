# AI比价三表流程发现记录

创建时间：2026-06-12

## 参考文档

- `docs/ai-price-three-table-workflow.md`：AI比价三表字段、状态、批次、推荐规则的锁定文档。
- `docs/miaoshou-skill-api-record.md`：妙手官方 skill/API 与 AI上架链路可用接口记录。

## 已确认决策

- AI比价先形成独立三表闭环，AI上架只读取表三 `状态 = 已审核` 的记录。
- 表三第一版不包含利润字段。
- 利润判断后续放在 AI上架模块或独立 `上架利润审核表`。
- 采购流程另开卡片，不进入当前计划。
- 表二必须保留 `商品组状态` 和 `候选状态` 两个字段。
- 表二到表三的生成触发条件为 `商品组状态 = 已核实 / 待更新表三`。
- 人工在飞书修改一行表二 `商品组状态` 后，系统下一轮扫描同步同组所有行。
- 表三支持手动按钮生成和自动扫描生成，第一版自动扫描默认关闭。
- 飞书模板按钮和本地 Excel 模板按钮都要做。

## 已确认表结构方向

表一：`输入表`

- 负责入口数据、郑和链接解析、去重、批次生成、失败归因。
- 关键字段：`商品ID`、`状态`、`国家/站点`、`郑和数据链接`、`原商品链接`、`原商品主图URL`、`当前比价批次号`、`失败归因`。

表二：`输出货源表`

- 保存 AI比价后的候选明细，不是最终上架结果。
- 关键字段：`商品ID`、`商品组状态`、`候选状态`、`采购总成本`、`克重`、`尺寸`、`人工指定上架货源`、`国家/站点`、`比价批次号`、`1688链接`、`offerId`、`SKU名称`、`采购价`、`运费`、`起批量`。

表三：`待人工核实上架表`

- 从表二生成唯一推荐货源，作为 AI上架/妙手采集入口。
- 关键字段：`商品ID`、`状态`、`采购总成本`、`克重`、`尺寸`、`妙手公共采集箱ID`、`妙手TikTok采集箱ID`、`妙手处理状态`、`推荐1688链接`、`offerId`、`推荐SKU名称`、`选择依据`、`失败归因`。

完整字段以锁定文档为准，避免多处维护造成漂移。

## 推荐算法记录

- 人工指定优先。
- 无人工指定时，按克重归组。
- 克重容差默认 `5g`，来自配置。
- 最高命中数的克重组胜出。
- 组内选择采购总成本最低候选。
- 多个克重组命中数相同时，选择组内最低采购总成本更低的组。
- 仍无法确定时，表三失败，失败归因为 `克重无法形成多数决策`。
- 人工指定多条候选时，表三失败，失败归因为 `人工指定多条候选`。

## 飞书与本地模板记录

飞书模板规则：

- 缺表则建表。
- 有表则补缺字段。
- 不删除字段。
- 不修改已有字段类型。
- 类型冲突时停止并提示 `字段类型不匹配`。

本地 Excel 模板规则：

- 单个 `.xlsx`。
- 三个 sheet：`输入表`、`输出货源表`、`待人工核实上架表`。
- 只输出表头，不写示例数据。

## 妙手边界记录

- 妙手采集不属于 AI比价模块。
- AI上架从表三读取 `状态 = 已审核` 的记录。
- 第一版不自动发布。
- 妙手官方 skill/API 已记录在 `docs/miaoshou-skill-api-record.md`。
- 表三中的妙手字段用于后续 AI上架回写，不由当前比价流程主动采集。

## 2026-06-12：真实跑通后的规则修正

- AI比价真实流程已跑通，当前可靠入口是表一 `状态 = 待处理`。
- 若表一没有 `待处理` 记录，单行执行会安全返回 `没有待处理记录`，不会擅自重跑旧记录。
- 重跑同一 `商品ID + 国家/站点` 会被三表去重拦截；除非人工清理旧表二/表三记录，或后续另做“强制重跑”入口。
- 表二默认 `商品组状态 = 待核实`，这是正确状态；它表示比价候选已生成，等待人工确认。
- 表三只应由表二 `商品组状态 = 已核实 / 待更新表三` 触发。
- 自动生成表三必须限定当前 `比价批次号`；否则新商品运行后可能扫描旧的已核实商品组，造成日志误导。
- `起批量` 已确认为参考值：可以是 `2000`、`3000` 等，不作为表三失败条件，只记录到字段和风险备注。
- 当前表三硬校验不再要求 `offerId`、`SKU名称`、`尺寸`、`起批量 = 1`。
- 当前表三仍要求可形成推荐所需的基础字段：商品ID、国家/站点、1688链接、采购价、运费、采购总成本、克重。
