## 2026-06-03：真实采购数据采集规则

- 列表页不能作为价格、克重、尺寸的可信来源。
- 列表页职责：
  1. 在前 N 个候选商品列表封面中，先找与 Excel 原图相似的商品。
  2. 仅保留候选链接、offerId、封面图、标题等初筛信息。
- 对每个通过初筛的候选商品，必须进入商品详情页。
- 详情页职责：
  1. 枚举商品所有 SKU。
  2. 程序逐个切换 SKU。
  3. 读取当前 SKU 图片。
  4. 将 SKU 图片与 Excel 原图做相似度对比。
  5. 只有 SKU 图片与原图相似时，才认为该 SKU 是同一件商品。
- 采购成本价获取规则：
  1. 选中匹配的 SKU。
  2. 数量设置为 1。
  3. 加购或触发下单/运费计算流程。
  4. 读取商品单价 + 运费。
  5. 该合计才是采购成本价。
- 属性采集规则：
  - 尺寸信息和克重信息必须从详情页、SKU 属性、规格参数、物流/运费相关区域中采集。
  - 若无法确定来源，需要记录置信度和风险备注。
- 当前 mock 候选中的价格、MOQ、克重只是占位数据，不代表真实采购成本。
- 后续输出字段需要区分：
  - 列表页候选信息
  - SKU 匹配结果
  - 采购成本价
  - 运费
  - 尺寸
  - 克重
  - 属性来源与置信度

## 2026-06-03：Chrome 当前窗口控制限制

- 用户期望：直接使用正在打开、正在登录的 Chrome，并在其中新开页签执行，不关闭浏览器。
- Playwright 限制：
  - 不能直接接管普通启动的 Chrome。
  - 只能连接已开启远程调试端口的 Chrome，或由 Playwright 自己启动浏览器。
- `launchPersistentContext` 使用现有 Chrome 用户数据目录时，会与已经打开的 Chrome 产生 profile 锁冲突，因此不适合用户“不要关 Chrome”的诉求。
- 当前方案：
  - 默认使用 `connectOverCDP` 连接当前 Chrome 调试端口。
  - 如果用户希望使用正在登录的 Chrome，需要先以 `--remote-debugging-port=9222` 启动 Chrome。
- 后续若要真正控制一个普通已打开 Chrome，可考虑浏览器扩展/Chrome DevTools Protocol 附加能力，但不是当前 Playwright 直接支持的模式。

## 2026-06-03：独立 Chrome 登录态方案

- 用户最终接受重新登录，不再要求接管当前普通 Chrome，也不希望恢复 CDP 调试链接配置。
- 当前产品方案：
  - 程序固定使用 Playwright 启动“应用独立 Chrome”。
  - Chrome 用户数据目录使用应用内部隐藏目录：`app.getPath('userData')/chrome-profile`。
  - 用户第一次执行真实任务前，点击“打开登录浏览器”，在这个独立 Chrome 里登录 1688。
  - 后续真实任务复用同一个 profile，因此会继承登录态、Cookie、本地存储等信息。
- UI 暴露范围：
  - 显示 Chrome 可执行程序路径选择器。
  - 显示“打开登录浏览器”按钮。
  - 不显示 Chrome 调用方式、Chrome CDP URL、Chrome 用户数据目录。
- Chrome 路径发现策略：
  - 如果 `chromeExecutablePath` 已保存，则直接使用，不重新自动探测覆盖。
  - 如果未保存，程序启动读取配置时按 macOS / Windows / Linux 常见安装路径查找。
  - 未找到时留空，让用户通过文件选择器选择 Chrome 可执行程序。
- 该方案不能复用用户当前正在使用的 Chrome profile 中已有插件/登录态；代价是用户需要在应用独立 Chrome 里重新登录一次，收益是任务自动化稳定、无需关闭用户日常 Chrome、无需调试端口配置。

## 2026-06-04：详情页克重与尺寸提取策略

- 仅靠程序可以提取一部分克重/尺寸，但不能保证稳定完整。
- 可程序稳定提取的情况：
  - 页面有明确字段名，例如“重量”“毛重”“净重”“包装尺寸”“产品尺寸”“规格”等。
  - 字段在结构化表格、属性列表、物流/运费模块中。
  - SKU 切换后字段会同步变化，并且 DOM 有稳定容器。
- 程序难以可靠判断的情况：
  - 克重/尺寸混在自然语言描述、图片详情、规格说明或客服话术中。
  - 多个 SKU 共用属性，但部分 SKU 有不同尺寸/重量。
  - 页面展示“约”“含包装”“一箱重量”“整包重量”等，需要语义判断。
- 推荐方案：
  1. 程序先在详情页结构化区域提取候选字段。
  2. 同时记录当前已选 SKU 名称、SKU 属性、商品标题、规格参数文本、物流/运费文本。
  3. 如果程序无法确定唯一克重/尺寸，或字段置信度低，则把这些文本连同选中 SKU 发给 AI。
  4. AI 返回结构化 JSON：`weightGram`、`dimensions`、`weightSource`、`weightConfidence`、`reason`。
- 重要约束：AI 不能凭空猜；如果页面信息不足，应返回“未识别”并给出原因。

## 2026-06-05：任务中断与浏览器静默边界

- 中断任务采用协作式取消：
  - 通过 `AbortController` 通知运行中的任务。
  - 长流程在关键 await 前后检查 `AbortSignal`。
  - 如果当前正在等待页面加载、AI 请求或 Playwright 操作，中断不会强杀 Node 进程，而是在当前步骤返回/超时/抛错后的最近检查点停止。
- 中断后的状态语义：
  - UI 立即显示 `cancelled`。
  - 后台任务最终也保持 `cancelled`。
  - 已生成的输入、图片、日志、部分输出资产不会自动删除，仍可通过日志定位。
- 删除运行中任务/清空日志时，也会先触发对应 controller 的 abort，避免后台继续写入已删除资产。
- Chrome 静默执行边界：
  - 当前为应用独立 Chrome + 持久 profile，必须保留非 headless，才能支持用户登录、Cookie、真实页面行为。
  - 已去除 `bringToFront()`，避免程序主动抢焦点。
  - 已添加 `--start-minimized`，让 Chrome 尽量最小化启动。
  - 但 Chrome/操作系统可能仍会在首次启动、新窗口创建或安全提示时短暂置顶；这不是 Playwright 完全可控的。
- 如果后续仍强烈打扰，可选方案：
  - 继续使用可见 Chrome，但任务开始后主动最小化窗口（需要额外 OS/窗口控制能力）。
  - 切换 headless 自动化，但可能破坏登录流程、页面行为或被 1688 风控识别。
  - 使用单独后台服务/虚拟显示器运行 Chrome，复杂度更高。

## 2026-06-06：详情页 DOM 与简化采集策略

## 2026-06-06：详情页起批量规则

- `dom/3.md` 的价格阶梯区域 `.od-price-container` 中包含起批信息，例如 `1个起批`、`50-399个`、`≥400个`。

## 2026-06-06：详情页真实价格读取顺序

- 正确顺序必须是：确认 `1个起批` → 选中最高相似 SKU → 数量设置为 1 → 等待价格栏更新 → 商品金额 + 运费。

  - 再 click/fill 数量输入框，并触发 input/change/blur。

  - 最后等待 `.order-select-models` 中出现 `已选1个` 和价格/运费文本。
- 如果价格栏未按预期更新，不应继续读取，应该让候选失败并记录原因，防止把旧价格当成采购价。

- 1688 价格阶梯里的起批单位会变化，不能只匹配 `个`。

## 2026-06-06：桌面端后台页面滚动策略

- 用户偏好是“信息密度更高、页面更简略、更清晰”，并尽量减少横向滚动条与全页长滚动。
- 当前页面适合的滚动策略：
  - 整个应用壳子固定为 `100vh`。
  - 主内容区允许整体纵向滚动。
  - 表格、日志、配置卡片等大内容块在超过可视高度时，优先使用区域内纵向滚动。
